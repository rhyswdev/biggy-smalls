# Schema authorities

Every source in a Smalls bundle has an authority for its shape, a way to check generated files against it, and a record of where we deliberately deviate. The files live under `schemas/`; paths in the table are relative to it. `bash schemas/fetch.sh` downloads the machine-readable ones (all URLs verified reachable from the cloud environment on 2026-10-12). `smalls_data/lint_schema.py` validates every generated file against the extracted schema or field list. Files fetched by the script are git-ignored; the extracted subsets under `schemas/<vendor>/extracted/` are committed.

Deviations we keep on purpose, recorded so the write-up can say so:

- Datadog monitor alert events carry `monitor_id`, `monitor_groups`, `is_aggregate` and `children` in real list responses but not in the v1 OpenAPI `Event` schema. We include `monitor_id`; the lint warns on unknown fields instead of failing for this source.
- Datadog v1 events is the legacy events API. We use it because its monitor alert events are what integrations like BigPanda's ingest.
- ServiceNow responses use `sysparm_display_value=true` (display strings only, times in the integration user's time zone with no marker), which the Table API reference documents. The `all` mode would return UTC alongside and defeat the timezone trap. The integration user's zone (America/New_York) is a property of the integration, recorded with the bundle.
